The expert team for each business area — HR, logistics, finance... Each section has several small helpers, each good at one job. The user doesn't see this detail; the conductor calls the right section.

Katman 3 · Domain Agents (Sonnet) — her grup bir veya daha çok ajanLayer 3 · Domain Agents (Sonnet) — one or more agents per section
Her iş alanının ana akıl yürütücüsü — İK, lojistik, finans, üretim, müşteri hizmetleri… Her grup bir Domain Agent'la (Sonnet — kompleks reasoning) temsil edilir. Domain Agent kullanıcı sorusunu anlar, doğru yardımcıları (Yatay + Veri ajanları) A2A ile çağırır, sentez yapar. Domain kapsamı ve genişleme sırası public görselin parçası değildir; gerçek uygulamada veri erişilebilirliği, entegrasyon yüzeyi, yetki modeli, insan onayı ihtiyacı, risk seviyesi ve kullanıcı etkisi gibi genel mühendislik kriterleriyle değerlendirilir.
The main reasoner for each business area — HR, logistics, finance, production, customer service… Each section is represented by a Domain Agent (Sonnet — complex reasoning). The Domain Agent understands the user's question, calls the right helpers (Horizontal + Data agents) via A2A, and synthesizes. The choice of domains and the order of expansion aren't part of this public diagram; in a real implementation they're assessed against general engineering criteria such as data availability, integration surface, the permission model, the need for human approval, risk level, and user impact.

Capability-based helpers that several domains need in common. Written once, they become a shared service for all sections. The brain is here (the reasoning: WHAT / TO WHOM / WHEN / WHICH CHANNEL); the mouth is in the L1 Channel (the carrier: a single API call). The Notification Agent up here decides "remind whom, tomorrow at 09:00", and the L1 Notification Channel just delivers the message.

Each data source is wrapped by its own agent (the Boundary Agent Doctrine). Top row: Data-Layer Agents — one per vendor, with an MCP server inside. Bottom row: federated data sources — they stay in place and aren't copied.

Her vendor için ayrı bir Data-Layer Agent + ayrı MCP server. Vendor protokol farklılıkları (OData, REST, SOAP, Graph) ajanın içinde encapsule. Kullanıcı tek dilden konuşur, ajan kaynağa özgü dile çevirir. Federe ilke: veri kaynakta kalır, kopyalanmaz, ETL/ambar yok — soru sorulduğu an çağrılır.
A separate Data-Layer Agent + separate MCP server for each vendor. Vendor protocol differences (OData, REST, SOAP, Graph) are encapsulated inside the agent. The user speaks one language; the agent translates to each source's own dialect. The federated principle: data stays at the source, isn't copied, no ETL/warehouse — it's called the moment a question is asked.

Veri kopyalanmaz, taşınmaz. Soru sorulduğu an çağrılır, birleştirilir, kullanıcıya tek bir cevap olarak döner. Tek tek araçlar değil — birlikte çalan bir orkestra. Federe mimari: kaynaklar yerinde; her sorgu A2A + service call zinciriyle anlık çözülür. Merkezi veri ambarı / ETL yoktur.

Data isn't copied or moved. It's called the moment a question is asked, combined, and returned to the user as a single answer. Not individual tools — an orchestra playing together. Federated architecture: sources stay in place; every query is resolved on the fly through an A2A + service-call chain. There is no central data warehouse / ETL.
